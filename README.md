# NAS115Sync — NAS ⇄ 115 網盤比對與即時同步（Windows 11）

在 Win11 電腦上執行，把 NAS 上所有資料夾與 115 網盤比對（檔名 + MD5 + SHA-1），
需要判斷的地方一律交給**本人核對**，其餘自動上傳；上傳時**優先觸發 115 秒傳**，
並可像 **OneDrive 桌面同步**一樣持續監看、隨時同步；遊戲存檔（savedata）可像
**Steam 雲存檔**一樣，遊戲寫完存檔後自動上傳到 115 對應資料夾並刪除 115 上的舊版。

> ⚠️ 本程式透過 **115 開放平台 API** 上傳與比對，沒有在真實 115 帳號上實測過（開發環境無法連線 115）。
> 請先用「示範模式」熟悉流程，再以少量資料夾實際試用，確認無誤後再擴大範圍。

## 需求對照

| 需求 | 本程式做法 |
|---|---|
| 在 Win11 PC 上執行 | Python + Tkinter 圖形介面，可打包成 `NAS115Sync.exe` |
| NAS 所有資料夾與 115 比對 | 「自動建議」列出 NAS 根目錄下所有資料夾，依名稱配對 115 資料夾 |
| 以檔名、MD5、SHA-1 比對 | 每個 NAS 檔案一次讀取同時計算 MD5、SHA-1（結果快取，不重算）；115 端使用其提供的 SHA-1 |
| **比對路徑要本人核對** | 每組 NAS⇄115 對應都必須在「核對確認」視窗看過兩邊內容、勾選「我已本人核對」才會同步 |
| **相同檔名或 MD5 或 SHA-1 要本人核對** | 同檔名不同內容、相同 MD5/SHA-1 出現在別處、同檔名出現在別的資料夾，都列入「待核對」 |
| **savedata 遊戲存檔要本人核對** | 偵測到存檔資料夾時先列入「待核對」，本人核可後才啟用自動同步 |
| 存檔像 Steam 雲存檔 | 核可後：存檔變動 → 靜置（且遊戲程序結束）→ 上傳新版 → **刪除 115 舊版**（可改為保留 N 份） |
| 用 115 上傳、盡可能觸發秒傳 | 每次上傳都先送整檔 SHA-1 + 前 128KB SHA-1 + 二次驗證（與 115 瀏覽器／客戶端相同的秒傳機制）；批次同步時先對全部檔案嘗試秒傳，再實際上傳其餘檔案 |
| 像 OneDrive 一樣時時同步 | 監看 NAS 檔案變動，新增／修改／改名／搬移／刪除即時反映；另有定期完整比對補抓漏掉的事件 |

### 關於「用 115 瀏覽器上傳」

115 瀏覽器本身沒有可供程式呼叫的上傳介面，用程式去點 115 瀏覽器的畫面既不穩定也無法大量處理。
本程式改用 **115 官方開放平台 API**，上傳流程與 115 瀏覽器相同（同一套秒傳判斷：
`fileid`=整檔 SHA-1、`preid`=前 128KB SHA-1、必要時依 `sign_check` 計算指定區段 SHA-1 做二次驗證），
所以 115 上已有相同內容的檔案時一樣會秒傳完成。
需要人工確認時，程式提供「**在 115 瀏覽器開啟**」按鈕，會用 115 瀏覽器（找不到則用預設瀏覽器）
直接打開對應的 115 資料夾讓你比對。

## 安裝

### 方式一：用 Python 執行（建議先用這個試用）

1. 安裝 [Python 3.10 以上](https://www.python.org/downloads/)（安裝時勾選 **Add python.exe to PATH**）
2. 下載本專案，雙擊 **`install.bat`**（建立虛擬環境並安裝套件）
3. 雙擊 **`run_demo.bat`** 用示範模式試用（模擬 115，不需帳號、不會連線）
4. 正式使用雙擊 **`run_gui.bat`**

### 方式二：打包成 exe

雙擊 **`build_exe.bat`**，完成後執行 `dist\NAS115Sync\NAS115Sync.exe`
（整個 `dist\NAS115Sync` 資料夾可複製到別台 Win11 電腦使用）。

## 登入 115

本程式使用 [115 開放平台](https://open.115.com/)，有兩種登入方式（「總覽」頁）：

- **115 App 掃碼登入**：需要 115 開放平台的 **AppID**（到 115 開放平台申請開發者應用後取得）。
  第一次按下會要求輸入 AppID，接著用手機 115 App 掃 QR 碼並確認授權。
- **貼上 refresh_token**：如果你已經用其他支援 115 開放平台的工具取得 refresh_token，可直接貼上。

登入資訊以 Windows DPAPI 加密存放（只有目前的 Windows 使用者能解開），access_token 會自動更新。

## 使用步驟

1. **路徑對應** → 「自動建議（NAS 所有資料夾）」：選 NAS 根目錄（例如 `\\NAS\home` 或 `Z:\`）與 115 根目錄
   （例如 `/NAS備份`），程式會把 NAS 每個資料夾配對到 115 同名資料夾。也可以「新增…」手動建立對應。
2. 選取每一筆對應 → **核對確認**：視窗會同時列出 NAS 與 115 兩邊第一層內容、兩邊同名項目、
   與其他對應重疊的警告，可按「開啟 NAS 資料夾」「在 115 瀏覽器開啟」實際查看；
   勾選「我已本人核對」後才能確認。**未核對的對應不會被比對或同步。**
3. **總覽** → **① 掃描比對**：計算 MD5/SHA-1（第一次較久，之後只重算有變動的檔案）並讀取 115 目錄，
   顯示每組對應「待上傳／已相同／待核對／僅 115 有」的數量。這一步不會上傳任何東西。
4. **待核對** 頁逐項（或同類型多選）處理需要本人判斷的項目。
5. **總覽** → **② 執行同步**：自動上傳可直接處理的檔案（先全部嘗試秒傳，再實際上傳其餘檔案）。
6. **總覽** → **▶ 開始即時同步**：之後 NAS 有任何變動都會自動處理。
   在「設定」勾選「Windows 開機時自動啟動」即可開機後自動開始同步。

## 比對規則

| 情況 | 處理 |
|---|---|
| 同路徑、SHA-1 相同 | 已同步，記錄「同步基準」（不重複上傳） |
| 同路徑、內容不同，尚無同步基準 | **待核對**：以 NAS 版覆蓋／保留兩者（115 舊版改名）／保留 115 版／略過／永久忽略 |
| 已同步過的檔案在 NAS 被修改 | 自動上傳新版並刪除 115 舊版（設定可改為「待核對」） |
| 已同步過的檔案在 115 被別人修改 | **待核對** |
| NAS 新檔案，但相同 SHA-1 或 MD5 已在 115 或 NAS 其他位置 | **待核對**（上傳必定秒傳）；若原位置的檔案已從 NAS 消失，會判斷為「搬移」，可直接在 115 搬移原檔 |
| NAS 新檔案，115 其他資料夾有同檔名檔案 | **待核對** |
| 115 同一資料夾有多個同名檔 | **待核對**：可刪除多餘的同名檔 |
| 已同步檔案在 NAS 被刪除 | 預設 **待核對**（可設為自動刪除 115 檔案，刪除會進 115 回收站） |
| 只有 115 有的檔案 | 只列在比對結果中，不會刪除也不會下載 |
| 遊戲存檔資料夾第一次出現 | **待核對**（見下節） |

> 115 只提供檔案的 SHA-1；MD5 由本程式在 NAS 端計算，並記錄每個已上傳檔案的 MD5，用來比對 NAS 各處及已上傳檔案的 MD5。

### 安全設計

- 只有本人核對過的路徑對應才會同步。
- 預設不會因為 NAS 刪除檔案而刪除 115 上的檔案。
- **NAS 離線保護**：NAS 根目錄無法存取時整組略過；一次出現大量「刪除」（預設 ≥20 個且 ≥30%）時一律暫停並列入待核對。
- 替換檔案時一律「先上傳新版、成功後才刪除 115 舊版」，不會先刪後傳。
- 115 上刪除的檔案會進入 115 回收站，可以復原。

## 遊戲存檔（Steam 雲存檔式同步）

- 自動偵測：路徑中有 `SaveData`、`Saves`、`SaveGames`、`Saved Games`、`存檔` 等資料夾，
  或副檔名為 `.sav`、`.sl2`、`.ess` 等（可在「設定」修改），即視為一個「存檔群組」。
  新增對應時勾選「整個資料夾都是遊戲存檔」則每個子資料夾為一個遊戲的存檔群組。
- 第一次偵測到時列入「待核對」，可選擇：
  - **核可：像 Steam 雲存檔自動同步**（可填遊戲執行檔名稱，例如 `eldenring.exe`）
  - 當一般檔案處理
  - 不同步此資料夾
- 核可後：存檔有變動 → 等存檔靜置（預設 60 秒）且指定的遊戲程序已結束 → 上傳變動的存檔到 115 對應資料夾 →
  **刪除 115 上的舊版**，讓 115 永遠是最新存檔。在「設定」把「115 保留存檔舊版份數」設為 N，
  舊版會改移到 `.savedata_versions` 資料夾並只保留最近 N 份。
- NAS 上刪除的存檔會同步刪除 115 上的存檔（可在設定關閉）。
- 115 上的存檔若被別台裝置改過（和上次同步不同），不會覆蓋，會列入待核對。
- 「遊戲存檔」頁可隨時變更狀態、設定遊戲程序、立即同步。

## 即時同步說明

- 監看 NAS 資料夾的新增、修改、改名、搬移、刪除事件。檔案停止變動（預設 5 秒）後才處理，避免上傳寫到一半的檔案。
- NAS 上改名或搬移已同步的檔案／資料夾，會直接在 115 改名或搬移，不需重新上傳。
- 網路磁碟（SMB）偶爾會漏掉事件，所以每隔一段時間（預設 15 分鐘）自動做一次完整比對。
  若 NAS 完全不回報變動事件，可在設定勾選「改用輪詢監看」。
- NAS 斷線時暫停監看，恢復連線後自動重新監看並補做完整比對。
- 方向是 **NAS → 115**（以 NAS 為主）；只在 115 上的檔案不會自動下載到 NAS。

## 注意事項與限制

- 115 開放平台需要 AppID；API 有呼叫頻率限制，程式預設每次呼叫間隔 0.4 秒並在被限流時自動等待重試。
  第一次讀取很大的 115 目錄會比較久。
- 第一次比對需要把 NAS 所有檔案完整讀一次以計算 MD5/SHA-1（經由網路讀取 NAS，TB 級資料需要數小時），之後只計算有變動的檔案。
- 實際上傳（非秒傳）的大檔會分片上傳到 115 的儲存服務；中斷時會從頭重傳該檔案。
- 115 API 若有變動，可能需要更新程式（相關程式碼集中在 `nas115sync/cloud/open115.py`）。

## 開發

```bash
pip install -r requirements-dev.txt
pytest                 # 單元測試＋以模擬 115 進行的整合測試（含即時監看）
python -m nas115sync --demo   # 示範模式
```

程式結構：

| 模組 | 說明 |
|---|---|
| `nas115sync/hashing.py` | 一次讀取同時算 MD5、SHA-1、前 128KB SHA-1；二次驗證區段 SHA-1 |
| `nas115sync/cloud/open115.py` | 115 開放平台客戶端（登入、目錄、秒傳／二次驗證、上傳） |
| `nas115sync/cloud/oss_upload.py` | 非秒傳檔案的分片上傳與 115 回呼 |
| `nas115sync/cloud/fake.py` | 模擬 115（測試與示範模式） |
| `nas115sync/compare.py` | 比對規則與待核對種類 |
| `nas115sync/engine.py` | 掃描、執行、核對決定、即時變動與存檔同步 |
| `nas115sync/watcher.py` | 即時監看、防抖、存檔靜置／遊戲程序偵測、定期完整比對 |
| `nas115sync/gui/` | 圖形介面 |
